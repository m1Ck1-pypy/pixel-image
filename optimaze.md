# План оптимизации: параллелизация и потоковая запись

Резервный план на будущее. Актуальное состояние: `--release` даёт 1.58 с
(было 89.88 с в dev-профиле), дальнейшие правки — только если понадобится.

После разделения на workspace логика лежит в `crates/core`, консольный слой — в
`crates/cli`. Пути ниже обновлены под эту раскладку.

Ожидаемый выигрыш: до ~2× (с 1.58 с до ~0.6–0.8 с). Потолок упирается в
однопоточное PNG-сжатие 402-мегапиксельного изображения и пропускную
способность памяти. Порядок этапов — по соотношению польза/риск.

## Шаг 0. Тайминги по этапам (обязателен)

До любых оптимизаций добавить замер `Instant` вокруг каждого этапа в
`crates/core/src/pipeline.rs` (очистка, уменьшение, гистограмма+палитра, ремап,
увеличение+сетка), а сохранение замерить в `convert_file`. Выводить при флаге
`--verbose` (добавить в `crates/cli/src/args.rs` и печатать в `main.rs`).

Без замеров нельзя подтвердить эффект каждой правки — не пропускать.

## Шаг 1. Зависимости

- `rayon` в `[workspace.dependencies]` и `crates/core/Cargo.toml` (для
  `par_iter`, `par_chunks_mut`, `fold`).
- `png = "0.18"` как прямую зависимость `crates/core` для потоковой записи
  (уже в дереве, транзитивно через `image 0.25.10`, версия совпадает с
  `Cargo.lock`).

Детерминированность: все параллельные участки пишут в непересекающиеся
диапазоны строк/пикселей, порядок записи на результат не влияет — вывод
остаётся байтово воспроизводимым (кроме смены компрессии PNG на шаге 5).

## Шаг 2. Параллельная сетка — `crates/core/src/grid.rs::upscale_with_grid`

Самый жирный участок. Строки ячеек `gy` независимы: маска непрозрачности
считается заранее по спрайту (512×768), `grid_over` — чистая функция без
состояния.

- `par_iter` по `0..h`, каждый таск считает свой диапазон строк выходного
  буфера `buf[gy*cell*out_w*4 ..]` и пишет только в него.
- Сохранить ранний `continue` для прозрачных ячеек вдали от персонажа.
- Внутри ячейки двойной цикл `dy/dx` (32×32 = 1024 итерации) не распараллеливать —
  таск уровня ячейки достаточно мелок.

## Шаг 3. Параллельная упаковка при сохранении — `crates/core/src/pipeline.rs::save_png`

Оба прохода — композит с фоном (`bg`) и упаковка RGBA→RGB — чистые
поэлементные преобразования:

- `raw.par_chunks_exact(4)` (или чанки по строкам) → сборка `out` по
  предвычисленным смещениям (chunk index × 3), либо `fold` по диапазонам
  строк с последующей склейкой.
- Проверка «все ли непрозрачные» тоже на `par_iter`.

## Шаг 4. Параллельная мелочь (дёшево, почти без риска)

- `crates/core/src/downscale.rs::downscale_resize`: премультипликация и депремультипликация —
  `par_chunks_exact(4)` / `par_chunks_exact_mut(4)`.
- `crates/core/src/downscale.rs::apply_alpha_threshold` — `par_chunks_mut`.
- `crates/core/src/palette.rs::histogram` — `fold` с `HashMap` на поток + слияние
  (сортировка после слияния сохраняет воспроизводимость).
- `crates/core/src/clean.rs::cut_faint_alpha` — `par_chunks_mut`.

## Шаг 5. Потоковая запись PNG — убрать промежуточные буферы

Сейчас пик памяти: 1.6 ГБ (RGBA сетки) + 1.2 ГБ (RGB копия) + выходной PNG.
Цель: писать в `png::Encoder` построчно, не материализуя копии.

- Переделать `upscale_with_grid` в генератор строк: функция, заполняющая
  буфер одной строки `out_w × 4` (64 КБ) по номеру строки. Логика границ
  ячеек считается от `gy = y / cell`, состояние между строками не нужно.
  Параллелизм сохраняется: строки генерируются по диапазонам через `par_iter`.
- В `convert_image` сетка больше не создаётся целиком: строки идут сразу в
  энкодер `png::Encoder::write_header` + `write_image_data`.
- Композит с `--background` и выбор RGB/RGBA выполнять на лету на строке:
  RGBA только если в ней есть прозрачные пиксели (проверять заранее по
  маске спрайта, без сканирования 402 Мп).
- `CompressionType::Balanced` или `Fast` вместо умолчания — fdeflate
  однопоточный, это оставшийся потолок скорости.
- Спрайт (512×768) трогать не обязательно — он мал.

## Шаг 6. Проверка

1. До правок сохранить эталонные `test_grid.png` / `test_sprite.png`.
2. После каждого шага: `cargo test --workspace` + сверка результата попиксельно
   с эталоном (байтовое сравнение PNG с шага 5 не годится — смена компрессии
   меняет байты).
3. Замеры `--verbose` на `test.jpg -w 512 -s 32` после каждого шага.

## За пределами плана (алгоритмические, не параллелизм)

Необязательно; смотреть только если замеры покажут узкие места:

- `crates/core/src/clean.rs::remove_background`: маска `is_bg` одним проходом +
  scanline-заливка вместо попиксельного стека (сейчас `dist` считается до 5 раз
  на пиксель).
- `crates/core/src/clean.rs::defringe` / `remove_thin_pockets`: предвычислять
  `near`/маски вместо повторных проверок.
- `crates/core/src/palette.rs::median_cut`: `BinaryHeap` с SSE коробок вместо
  полного пересчёта на каждой итерации.
- Ремап цветов через LUT (5 бит/канал, 32 768 записей) — O(1) на пиксель.
- Ресайз: `fast_image_resize` (SIMD + rayon) вместо `imageops::resize`.
